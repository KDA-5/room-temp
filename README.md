# 강의실 상태판

36명이 **익명으로** 희망 온도를 찍으면, 합의 타점이 표가 몰린 쪽으로 움직입니다.
매 정각마다 "지금 에어컨을 바꿔야 하는지"를 알려주고, 강의 난이도·속도 피드백도 같이 받습니다.

로그인 없이 링크만 있으면 누구나 들어와서 투표할 수 있습니다.

## 뭐가 들어 있나

| 기능 | 설명 |
|---|---|
| **온도 투표** | 0.5°C 단위 슬라이더. 캐릭터 하나가 한 사람이고, 합의 타점에서 멀수록 표정이 힘들어집니다 |
| **정각 리듬** | 다음 조절까지 남은 시간이 카운트다운됩니다. 정각이 되면 그 시점 집계로 도장을 찍고, 0.5°C 이상 벌어졌을 때만 "바꾸세요"가 뜹니다 |
| **강의 피드백** | 난이도 · 속도를 5단계로. **정각마다 초기화**되고, 시간별 추이 그래프로 어느 교시가 힘들었는지 보입니다 |
| **자리별 분석** | 앞/뒤 × 창가/가운데/복도 6구역. 의견이 갈리면 대부분 온도가 아니라 자리 문제라서, 어느 구역이 추운지 짚어줍니다 |
| **캐릭터** | 색 14 × 머리 8 × 소품 10 × 무늬 6 × 손에 든 것 8 = **53,760가지**. 전부 코드로 그려서 이미지 파일이 없습니다 |
| **쉬는 시간 타이머** | 아무나 5·10·15·20분을 시작하면 전원 화면이 같은 카운트다운으로 바뀝니다. 끝나면 알림 |
| **익명 질문함** | 손 들기 어려운 질문을 익명으로. 공감 수로 우선순위가 생기고, 답변 완료를 찍으면 아래로 내려갑니다 |
| **자유게시판** | 잡담 · 질문 · 요청 · 정보 네 갈래로 필터. 링크는 자동으로 눌러 들어갈 수 있게 되고, 📌 고정은 최대 5개 |
| **접속자 수 · 환기** | "지금 12명 보는 중" 표시. 마지막 환기에서 50분이 지나면 창문 열라고 알려줍니다 |
| **날씨 · 습도** | 실시간 실외 기온/습도, 불쾌지수, ASHRAE 적응 쾌적 온도. 실내 온습도계 값도 넣을 수 있습니다 |
| **오늘의 잡학** | 온도·습도·쾌적에 관한 상식 22개가 날마다 돌아갑니다 |
| **슬랙 알림** | 평일 아침 요약 + 온도를 바꿔야 하는 정각에만 알림 (선택) |
| **QR · PWA** | 강의실 화면에 QR 띄우면 바로 접속. 휴대폰 홈 화면에 추가도 됩니다 |

### 타점을 절사평균으로 정하는 이유

| 방식 | 문제 |
|---|---|
| 평균 | 36명 중 한 명이 장난으로 18도를 찍으면 전체가 끌려갑니다 |
| 최빈값 | 36명 표본에서 불안정해서 0.5도 칸 하나 차이로 튑니다 |
| 중앙값 | 극단값엔 면역이지만 **계단식으로 점프**합니다. 부드럽게 움직이는 타점이 안 나와요 |
| **20% 절사평균** ✅ | 양 끝 20%씩(7명씩) 버려서 극단값에 면역이면서, 표가 움직이면 타점이 **연속적으로** 따라옵니다 |

수학적으로 `Σ|희망 − 설정|`을 최소화하면 중앙값, `Σ(희망 − 설정)²`을 최소화하면 평균입니다.
절사평균은 정확히 그 둘 사이예요. 올림픽 체조에서 최고점·최저점을 빼는 것과 같은 원리입니다.

### 계절별로 자르는 이유

같은 사람이 여름엔 26도, 겨울엔 22도가 쾌적합니다. 취향이 아니라 옷 두께(clo) 차이예요.
투표는 자유롭게 받되, **최종 설정온도만** 아래 밴드로 자릅니다.

| 계절 | 슬라이더 | 설정 허용 밴드 | 기본값 |
|---|---|---|---|
| 여름 (6–9월) | 22–30 | **24–28°C** | 26.0 |
| 간절기 (4–5, 10–11월) | 19–28 | **21–26°C** | 23.5 |
| 겨울 (12–3월) | 17–26 | **19–23°C** | 21.0 |

근거는 정부 권장(공공기관 냉방 28도·난방 18도)과 ASHRAE 55 적응 쾌적 모델
`쾌적온도 = 0.31 × 실외 평균기온 + 17.8` 입니다.

## 설치

### 1. 내려받고 의존성 설치

```bash
cd room-temp
npm install
```

### 2. Supabase 프로젝트 만들기

1. [supabase.com](https://supabase.com) → 무료 계정 → **New project**
2. 프로젝트가 다 뜨면 **Authentication → Sign In / Providers →
   "Anonymous sign-ins" 를 Enable** 로 켜주세요.
   👉 **이걸 안 켜면 아무도 로그인이 안 되고 투표도 안 됩니다.**
3. **SQL Editor** → `supabase/schema.sql` 을 통째로 붙여넣고 **Run**
   - 테이블, 접근 권한(RLS), 정각 기록 함수까지 한 번에 만들어집니다
   - **몇 번을 다시 돌려도 안전합니다.** 나중에 기능이 늘어서 이 파일이 바뀌면,
     이미 만든 DB 에 그대로 다시 붙여넣기만 하면 새 컬럼·함수만 붙습니다

### 3. 환경변수

```bash
cp .env.example .env      # Windows PowerShell 이면: Copy-Item .env.example .env
```

`.env` 를 열고 채웁니다. Supabase **Project Settings → Data API** 에서 복사하세요.

```ini
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
VITE_ROOM_SIZE=36
VITE_LAT=37.5665       # 강의실 위치 (날씨용). 기본은 서울
VITE_LON=126.9780
```

> `anon key` 는 원래 브라우저에 공개되는 키라 노출돼도 괜찮습니다.
> 실제 보호는 `schema.sql` 의 RLS 정책이 합니다.
> `service_role` 키는 절대 `VITE_` 를 붙이지 마세요.

### 4. 돌려보기

```bash
npm run dev     # http://localhost:5173
```

슬라이더를 움직였을 때 오른쪽에 **"저장됨 ✓"** 가 뜨면 성공입니다.

## 배포 (Vercel)

```bash
git init
git add -A
git commit -m "강의실 상태판"
gh repo create room-temp --private --source=. --push   # 또는 GitHub 에서 직접
```

1. [vercel.com](https://vercel.com) → **Add New → Project** → 방금 만든 저장소 선택
2. 프레임워크는 **Vite** 로 자동 인식됩니다. 그대로 두세요.
3. **Environment Variables** 에 `.env` 의 값을 그대로 넣습니다
   (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_ROOM_SIZE`, `VITE_LAT`, `VITE_LON`)
4. **Deploy**

끝나면 `https://room-temp-xxxx.vercel.app` 같은 주소가 나옵니다.
그 주소를 슬랙에 올리면 링크만으로 다들 들어옵니다.

### 슬랙 알림 (선택)

안 해도 앱은 멀쩡히 돌아갑니다. 켜고 싶으면:

1. [api.slack.com/apps](https://api.slack.com/apps) → **Create New App → From scratch**
2. **Incoming Webhooks** → 활성화 → **Add New Webhook to Workspace** → 채널 선택
3. 나온 웹훅 주소를 Vercel **Environment Variables** 에 추가 (`VITE_` 없이!)

```ini
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
PUBLIC_SITE_URL=https://room-temp-xxxx.vercel.app
```

- **평일 아침 9시(KST)** 에 오늘의 권장 온도 요약이 갑니다 (`vercel.json` 의 크론)
- **정각에 온도를 바꿔야 할 때만** 추가 알림이 갑니다. 바꿀 필요 없으면 조용합니다
- 같은 정각에 36명이 동시에 접속해 있어도 알림은 **한 번만** 나갑니다
  (`record_checkpoint()` 가 DB 에서 중복을 막습니다)

## 개인정보를 어떻게 지키나

- **이름도 이메일도 안 받습니다.** 브라우저마다 Supabase 익명 계정이 하나 생길 뿐이에요
- **투표 테이블은 본인 행만 읽을 수 있습니다.** 남들이 보는 건 `uid` 를 뺀 `votes_public` 뷰라,
  게시판 닉네임과 투표 기록을 이어붙여서 "쟤가 몇 도 찍었네" 하는 게 **구조적으로 불가능**합니다
- **그래프에서는 기본이 익명입니다.** 닉네임을 보여줄지는 각자 켜야 합니다
- **자리 구역 평균은 4명 이상 모였을 때만** 공개됩니다. 2명짜리 구역은 역추적이 되니까요
- 남의 표를 덮어쓰거나 남의 글을 지우는 건 DB 정책(RLS)이 막습니다. 클라이언트만 막으면 뚫려요

## 한 학기(3달) 버티나

전부 무료 요금제로 됩니다. 36명이 **하루 8시간 내내 탭을 켜둔** 최악의 경우로 계산한 값입니다.
실제로는 이보다 훨씬 적게 나옵니다.

| 항목 | 예상 사용량 | 무료 한도 | 여유 |
|---|---|---|---|
| Supabase 전송량 | 월 **2.1 GB** | 5 GB / 월 | 42% |
| Supabase 저장공간 | 3달 누적 **5 MB 미만** | 500 MB | 1% |
| Supabase 실시간 메시지 | 월 약 16만 건 | 200만 건 | 8% |
| Vercel 전송량 | 월 약 0.3 GB | 100 GB | 0.3% |
| Vercel 함수 호출 | 월 약 200회 | 100,000회 | 0.2% |

전송량은 **매달 초기화**되므로 3달이든 1년이든 똑같습니다.
저장공간만 누적되는데, 투표는 36행으로 고정(덮어쓰기)이고 게시글도 3달에 1.4 MB 수준입니다.

### 전송량을 어떻게 줄였나

처음엔 25초마다 전부 다시 읽는 구조였는데, 그러면 **월 42 GB**로 한도를 3일 만에 태웁니다.
그래서 세 가지를 바꿨습니다 (`src/supa.js`):

1. **바뀐 조각만 읽기** — 브로드캐스트에 `scope`(votes / posts / meta)를 실어 보냅니다.
   투표 하나 바뀌면 7 KB만 다시 읽지, 게시판 28 KB까지 끌어오지 않아요.
2. **1.5초 합치기** — 여러 명이 동시에 슬라이더를 움직여도 한 번만 다시 읽습니다.
3. **폴링 간격** — 3분마다 투표만, 30분마다 전체. 탭이 뒤에 있으면 아예 안 합니다.

**42 GB → 2.1 GB, 20배 감소.** 사람이 더 늘거나 여유가 필요하면
`POLL_MS`(3분) · `FULL_MS`(30분) · `POST_LIMIT`(30개)를 키우면 됩니다.

### ⚠️ 딱 하나 주의할 것: 프로젝트 일시정지

**Supabase 무료 프로젝트는 7일간 아무 접속이 없으면 자동으로 일시정지됩니다.**

- 학기 중 평일에 쓰는 동안은 걱정 없습니다. 주말 이틀은 괜찮아요.
- **일주일 넘는 방학·연휴가 끼면 정지될 수 있습니다.**
- 정지돼도 **데이터는 그대로 남습니다.** Supabase 대시보드에서 `Restore` 한 번 누르면
  몇 분 뒤 되살아나요.
- 방학 중에 누구든 한 번씩 사이트를 열어주면 아예 정지되지 않습니다.
